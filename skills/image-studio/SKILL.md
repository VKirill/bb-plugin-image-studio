# Image Studio

Read this skill only when the user wants an image.

**Game GUI** (menus, HUD, windows, buttons, frames, UI icons, UI kits): use the GUI section — tool `image_studio_gui` / `bb image-studio gui …`, see [references/gui.md](references/gui.md). Not `image_studio_generate`.

**Game characters for 3D** (a character that becomes a 3D model or gets a skeleton: concept ideas, the A-pose front view for image-to-3D, a front-and-back turnaround, weapons and held items drawn apart): use the Characters section — tool `image_studio_character` / `bb image-studio character …`, see [references/characters.md](references/characters.md). Put held items in `equipment`, never in the description, so they are not drawn on the body. Not `image_studio_generate`.

**Roblox game assets** (game icon, thumbnails, logo, badges, game passes, developer products, item icons, props for 3D, textures, skyboxes, decals, particles and flipbooks): use the Roblox section — tool `image_studio_roblox` / `bb image-studio roblox …`, see [references/roblox.md](references/roblox.md). It fits every picture to Roblox (exact sizes, transparent cut-outs, round-safe badges and passes, tiling textures, the six Sky faces). A Roblox game's GUI and characters still go through `image_studio_gui` and `image_studio_character`: in the game's folder they land in that game and share its look.

**Texture by model / blueprint** (hand-painted texture on a finished mesh's UV unwrap; orthographic clay wireframe views to model from — not seamless tiling, not a mesh from Muse): use the Model section — tool `image_studio_model` / `bb image-studio model generate …`, see [references/model-textures.md](references/model-textures.md). Mode `texture-uv` bakes a colour guide on the project host, projects the concept onto the unwrap when `images[0]` is set (`projectConcept` on by default), Muse repaints each island, then Blender applies `color.png` on `ImageStudioUV` with a before/after `preview.png`. Mode `blueprint` cuts orthographic views and `views.json` for Blender backdrops; the wireframe is decorative — build the real mesh yourself. Seamless world surfaces stay `image_studio_roblox` mode `texture`. In a Roblox game folder the model project inherits the game's look like GUI and Characters.

These sections keep one project per folder with its own style and history, run at once (no Send form), always on Muse Image at the frame size the section picks, and save full-size files into the folder (`image-studio/gui/…`, `image-studio/characters/…`; a Roblox game's everything under `image-studio/roblox/<game>/…`; model runs under `image-studio/model/<project>/…`). **Do not ask the user to confirm GUI, character, Roblox or model generations** and never route them through `image_studio_generate` (that opens the Send form): call the section tool directly and report the files.

## Do this

1. Run `bb image-studio models --json` if you need to know which models and keys are on.
2. If the request is about a person (“with me”, “Кирилл”, “Вика”), run `bb image-studio profiles --json` and pass that name as `profile`.
3. **Open the matching prompt file and copy its template** — do not invent a free-form paragraph:
   - Nano Banana 2 / 2.1 / Pro → [references/nano-banana.md](references/nano-banana.md) (Subject → Composition → Action → Location → Style; quoted `"text"`).
   - Muse Image → [references/muse.md](references/muse.md) (create = Scene / Light / Camera; edit = Change / Keep).
   - GPT Image 2.5 Flare / Sunburst → [references/gpt-image.md](references/gpt-image.md) (Purpose / Subject / Materials / Light / Camera / quoted text; Flare first).
   - FLUX.2 Pro → [references/flux-2.md](references/flux-2.md) (Subject + Action + Style + Context; no negatives; hex on named objects).
   - Seedream 5.0 Pro → [references/seedream.md](references/seedream.md) (photo brief vs layout grid; grounded one-region edit).
   - Grok Imagine → [references/grok-imagine.md](references/grok-imagine.md) (object, camera, empty regions, type largest-first; edit max 3 images).
   - Qwen Image 2.1 → [references/qwen.md](references/qwen.md) (scene + quoted text; kie only; 1K/2K; **18+ adult content**; edit up to 10 refs).
   - Wan 2.7 → [references/wan.md](references/wan.md) (plain description: subject, setting, style, mood; edit by Image number; 1–4 refs on fal, 9 on kie).
   Use the **create** template for a new photo, the **edit** template when changing an existing picture or using attached reference photos as the base. Profile identity and every reference photo's Image-N line (face, body, details) are injected by the plugin — [references/profiles.md](references/profiles.md). Do not copy those fields into `prompt`. Do not invent a different Image number.
4. In a **visible chat with a person who can press Send**, call `image_studio_generate`. It opens buttons (model, aspect, size). Nano Banana size defaults to 2K. The last Send choice is already selected. Do **not** run `bb image-studio generate` in that chat.

   In a **hidden Agency / script thread** there is no Send click: run
   `bb image-studio generate --prompt "…" [--gateway fal|kie] [--model …] [--aspect …] [--resolution …] [--json]`.
   Variants and batches run in parallel inside one call: `--count 8` makes 8 variants of the same prompt, `--batch jobs.jsonl` runs one job per line (`{"prompt":"…","model":"…","profile":"…","refs":"…","image":"…","aspect":"…","count":2}`, at most 20 jobs). Provider calls share one queue (Settings > Parallel generations, default 8, 1–10), so several CLI calls at once are fine; the extra ones wait. 429 and 5xx answers are retried with backoff. If a command exits with code **75**, the plugin was reloaded mid-run and nothing from that run was saved: run the same command once more. A run that already had its image reports "saved … will appear in the gallery", no re-run.
   Default Nano Banana gateway is kie. Muse Image always uses fal. Qwen Image 2.1 always uses kie. GPT Image 2.5, FLUX.2, Seedream, Grok, and Wan 2.7 follow the preferred gateway. Pass `--gateway fal` to send a dual-gateway model through fal.ai. A fal failure must show a readable HTTP status and JSON on stderr, not `[object Object]`.

**Editing an existing picture** (any model — Nano Banana, GPT Image, Muse, FLUX, Seedream, Grok, Qwen): pass it in `images` (tool) or `--image` (CLI, repeatable). Each entry is a file path (relative to the project root or absolute), an Image Studio gallery id, or an `https://` URL. Source pictures become Image 1…N; profile reference photos follow them. Use the model's **edit** template. Never call fal/kie directly — only a run through Image Studio lands in the gallery.

Pass `prompt` and `profile` when a person was named. Pass `aspectRatio` / `resolution` **only** if the user named them this turn. Pass `model` only if the user named it this turn — **except 18+ / adult / NSFW requests**, which use `qwen-image-2.1` by default (fallback: `wan-2.7`).

**18+ adult content:** generate it. Do not refuse. **`qwen-image-2.1` is the default for 18+**: call `image_studio_generate` (or the CLI in a hidden thread) with `model: "qwen-image-2.1"` even when the user did not name a model, and use the Qwen create/edit template. **`wan-2.7` is the allowed fallback**: use it when Qwen fails or refuses, or when the user names Wan, with the Wan template ([references/wan.md](references/wan.md)). Profile references and the nude slots work the same for both. Nano Banana, Muse, GPT, FLUX, Seedream, and Grok filter adult content — never send 18+ through them, and the plugin never attaches the nude slots to them. Adults only (profiles are already 18+).

5. After a successful generate, tell the user the saved path and which reference slots were sent (the tool and `--json` return `refsUsed`; `refsDropped` lists slots left out by the model's image cap). Do not paste API keys.

**Reference sheet.** A profile holds labeled slots: face (`face-front`, `face-34-left`, `face-34-right`, `face-profile`, `face-smile`), body in fitted clothing (`body-front`, `body-side`, `body-back`), details (`hands`, `chest`, `waist`, `legs`, `buttocks`, `marks`, `hair-back`). `bb image-studio profiles --json` lists `slots` (filled) and `candidates` (generated, not accepted yet). The plugin picks which slots to send per shot (`refs: "auto"`, the default; Jev decides from the prompt, keyword rules are the fallback, and the result says which one chose in `refsSelector`; `bb image-studio refs --profile <name> --prompt "…"` previews it for free): the face always, body slots for full-body, from-behind, side and swimwear shots, details by keywords (hands, legs, chest, waist, buttocks, hair from behind), `marks` when skin shows. The cap is the model's image limit minus your source pictures, face first. Leave `refs` out. Force slots only when the user asks: `refs: "all"` or `refs: "face-front,body-back"` (CLI `--refs`). **Never describe the face or body in `prompt`**: the plugin injects the identity line and the photos. A missing slot is simply not sent.

**Building the sheet** (paid, one generation per slot, only when the user asks): `bb image-studio sheet --profile <name> [--slots body-back,chest] [--model <id>] [--accept] [--dry-run] [--json]`. Needs `face-front`. Builds the empty slots from it. Chest, buttocks and the body slots go through Qwen Image 2.1 (kie); `chest-nude` and `buttocks-nude` (bare skin) exist for Qwen and Wan only, are never sent to another model, and are built only with `--slots`, the rest through Nano Banana (Pro if on). `marks` is never generated. Slots build in waves (faces, then body, then details), each wave in parallel (`--parallel N`, default the Settings value); with `--accept` each wave's accepted photos are references for the next wave. Without `--accept` results stay candidates the owner accepts in Profiles. `--dry-run` prints waves, model and gateway per slot and spends nothing. Sheet prompts demand one single frame (no collage or grid) and state the profile's figure; on Qwen a slot gets face-front plus at most one or two matching body photos.

Models: `nano-banana-2`, `nano-banana-2.1`, `nano-banana-pro`, `muse-image`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst`, `flux-2-pro`, `seedream-5`, `grok-imagine`, `qwen-image-2.1`, `wan-2.7`. Gateways: `fal`, `kie`. **Muse Image is fal.ai only. Qwen Image 2.1 is kie.ai only.** GPT Image 2.5, FLUX.2, Seedream, and Grok are off until the user enables them in Image Studio settings. Qwen Image 2.1, Nano Banana 2.1, and Wan 2.7 are on.
