# image_studio_model mode blueprint: one Muse sheet (TZ 3.2 structured prompt, light grey background, labels), cut into views of one scale and baseline, side-copies-front check with a separate side draw, soft parts in light-blue clay with anchors, views.json

Implement mode blueprint of image_studio_model (today it throws 'not implemented'); read tz.md 3.2 and 3.4. Input: images[0] = concept (required), views (subset of front|side|back|top, default front, side, back, in that order), style 'clay+wire' (default) | 'clean line', subject (default 'this object'), soft: string[] (parts that must dangle: cloth, ropes/threads, ribbons, hair, tails), rigid?: string[]. Prompt (src/blueprint.ts buildBlueprintPrompt) follows TZ 3.2: 'Image 1 is the DESIGN REFERENCE: {subject}.' / 'Task: draw a technical modeling blueprint of exactly this object for a 3D artist — {n} orthographic views side by side on a plain light grey background: FRONT, SIDE (exact 90° profile, not a copy of the front), BACK; same scale and height, aligned on one baseline; flat grey clay with a visible black quad wireframe (clean line: clean black outlines on flat grey clay); soft dangling parts ({list}) in light BLUE clay.' (omit the soft clause when none) / 'Must not change: the proportions, part count and silhouette of the object in image 1.' / 'No perspective, no shadows, no fire or effects, no text except the labels FRONT, SIDE, BACK.' Muse (muse-image, 16:9 for 3 views, 21:9 or 2:1 for 4 if supported). Cutting (pure TS on Rgba): key the plain light grey background sampled from the corners (tolerance), find views by column projection of foreground (gaps split views, merge slivers); in each column keep the largest connected component and anything touching it, drop small detached components (the labels and specks); expect views.length boxes, else a warning naming what was found; per view baseline = lowest opaque row; every view goes on one transparent canvas size (max w x max h + margin), sheet scale kept, bottoms on one baseline, centred → front.png, side.png, back.png, top.png; sheet.png = original. Side check (TZ 3.4: Muse often draws SIDE as a copy of FRONT): silhouetteSimilarity(front, side) on alpha masks normalised to the same height (IoU); above ~0.9 the plugin draws the side alone with buildSideOnlyPrompt ('Image 1 is the DESIGN REFERENCE … Task: draw only the exact 90° side profile of this object, seen edge-on … same clay style, plain light grey background … Must not change …'), cuts it the same way, scales it to the front's height and replaces the side; views.json sideRegenerated true. Soft parts: per view light-blue regions by colour key (hue/saturation range around SOFT_CLAY_HEX, connected components, ignore specks); anchor = mean of blue pixels touching grey clay, in canvas coordinates; anchors from the front view when present, else the first view with blue; a listed soft part with no blue anywhere → warning. views.json: {views:[{name,file,box:{x,y,w,h},baseline,heightPx}], canvas:{w,h,baseline}, parts:[{name,kind:'rigid'|'soft',anchor:{view,x,y}|null}], sideRegenerated, warnings}. Output: image-studio/model/<project>/<run>/blueprint/. Tool + CLI (`bb image-studio model generate --mode blueprint --image <concept> [--views front,side,back] [--style clay+wire|clean-line] [--soft "rags; rope"] [--subject "fire mop"]`) report the files and views.json.
